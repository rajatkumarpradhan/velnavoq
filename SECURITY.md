# Part 20 - Security review and hardening

10 October 2026. Scope: the Part19 source plus the fixes below, static-web-v1 control Worker/D1, React UI, QuickJS browser worker, preview host, static deployment target, OAuth reference client and MCP server. This is a source review with reproducible local adversarial tests against OWASP ASVS **5.0.0**. It is not ASVS certification, a complete Level 1/2/3 verification, an independent penetration test, or a claim that production is secure. No production deployment or account change was made.

## Fixed findings

- **High availability risk:** bounded bytes alone allowed deeply nested JSON into recursive canonical/secret walks. Iterative validation now caps depth at 32 and visited nodes at 20,000 before any recursive processing. Reserved prototype keys and invalid UTF-8 are rejected. A rejected request persists no workspace.
- **Medium abuse risk:** GET metadata, health and pre-auth failed write routes could bypass the existing write/auth rate limits while creating telemetry DB writes. All GET/HEAD requests now have a 240/minute per-trusted-IP bucket; other permitted methods have a 120/minute incoming bucket before authentication. Existing lower auth/write/MCP limits still apply. Oversized request targets and unsupported methods are rejected first. Old counters are pruned with an indexed window column. This is not distributed DDoS protection.
- **Medium credential ambiguity:** duplicate session cookies silently selected the first value. A shared session/OAuth parser now accepts exactly one 64-hex credential, rejecting both duplicate orders. Normal cookies and exact CSRF still work.
- **Medium defense-in-depth egress gap:** the OpenAI credential-bearing fetch inherited automatic redirect behavior. It now refuses redirects. The destination is still server-owned and fixed, not a client URL. Public deployment origins additionally reject literal IPs, private/metadata-style names, credentials, nondefault ports and the control hostname. Local target mode remains explicitly local only. DNS rebinding of a malicious operator-configured hostname is not solved by string validation.
- **Medium supply-chain gap:** pinned packages/lock integrity did not prevent dependency lifecycle hooks on future installs. Repository `.npmrc` sets `ignore-scripts=true` and `save-exact=true`; clean `npm ci` and both builds were verified with that policy. This reduces lifecycle-hook execution, not malicious code imported at runtime.
- **Medium audit coverage/integrity gap:** successful auth was only generic request telemetry and observation rows could be updated. Successful/failed auth now use metadata-only auth events; a D1 trigger refuses observation UPDATE. Retention and project-erasure DELETE still work. DB administrators can drop triggers/delete rows, so this is not independent tamper-proof storage.
- **Low unsafe namespace ambiguity:** bundle paths now reject `__proto__`, `constructor` and `prototype` segments, matching stricter editor/runtime rules. Object pollution is not claimed as a demonstrated exploit in the prior build.

## Production gates and residual risk

Do not enable production merely because these tests pass. Password auth stays disabled for public origins; Workers Free CPU budget for hashing/static parsing is unproven. Cloudflare access remains blocked and no public target exists. Real edge TLS/HSTS, IdP/MFA/recovery, idle/step-up controls, correct trusted proxy headers, edge abuse protection and sustained-load/quota tests need separate verification. Service bindings must remain separated from control DB/secrets. A preview/target must use a different hostname, not another port of the controller host.

The default browser sandbox is not a hardware/security proof or universal egress firewall. Generated apps may contain navigation links; CSP connect denial does not prove every network request impossible. Do not give untrusted code credentials or upgrade browser-reported builds/previews to production verification. Arbitrary Node/npm/full-stack execution remains disabled.

Public health-check names are operator-owned, not client-selected. Name filtering does not defend DNS rebinding or a compromised configured host; deployment requires a controlled static host and external egress/DNS controls if broader targets are introduced. Rate buckets protect local application paths only: failures still require bounded logging work, and a many-IP flood can exhaust Workers/D1 quotas. No paid firewall was silently introduced.

Retention is not forensic WORM storage. UPDATE protection can be bypassed by an administrator; DELETE is needed for retention/erasure. No external sink, alert delivery or time-sync evidence from production exists. Encryption/key custody, backup retention and target/orphan deletion remain operator obligations. Audit 0 vulnerabilities is a dated registry check, not package safety certification.

## Verification and reproduction

Final backend verification: **367 tests across 18 files (18 new Part20 tests)**, TypeScript and both Worker dry-runs pass, npm audit reports zero vulnerabilities. UI production build passes. Existing observability (21), deployment (18) and versioning (20) browser checks pass at 360/390/412/1440px with accessibility/no-overflow checks. Attack-matrix rendering adds 8 accessibility/no-overflow checks across the same four widths; actual 360/390px pixels were inspected. Populated migration, binary and SQL backup restore pass. These are local test results, not production traffic.

`npm ci` uses `.npmrc` lifecycle-hook suppression. `npm run check` runs TypeScript, both Worker dry-run builds, backend tests and npm audit. `npm run ui:build`; `node scripts/observability-check.mjs`; `node scripts/deployment-check.mjs`; `node scripts/versioning-check.mjs`; `node scripts/security-check.mjs`; `python3 scripts/check-backup.py`. Browser scripts require `npx playwright install chromium`.

Part20 tests are `tests/hardening.test.ts`. They execute real local workerd/D1 for duplicate sessions, JSON depth/no mutation, read and pre-auth write flood limits, expiry cleanup, method/URL/address bounds, auth-event classification and immutable-event trigger; unit adversarial tests cover UTF8, wide JSON, reserved keys/paths, public target restrictions, package policy and credential-redirect refusal. Existing 349 tests exercise the other matrix boundaries. AI transport tests are explicitly test-only; no paid model inference was made.
